# 场景能力可配置方案

状态：已按第三版落到代码。场景开关不区分管理员，全局默认只来自 `CAPABILITY_DEFAULT`。

## 现状

登录之后，这些场景人人都能进、都能改：

| 入口 | 路由 | 里面实际在写什么 |
| --- | --- | --- |
| 晨昏日志 | `/daily` | 时间记录、议题、语音/AI 解析 |
| 双周扫描 | `/week` | 周期正文 |
| 季度沙盘 | `/month` | 阶段正文、汇聚、AI 合成 |
| 知行录 | `/plans` | TED、健身、书/电影，三个独立功能 |
| 零钱罐子 | `/piggy-bank` | 罐子、流水、分配（从日报标题进入） |

数据已经按人分开。令牌在 `middleware` 里解析成 `x-user-id`，接口用 `getEffectiveUserIdFromRequest` 查自己的行。没令牌的人是旁观者：GET 看主账号数据，其它方法直接 401。这里的主账号只负责「旁观者看谁的数据」，和场景开关无关。

能力没有按人分开。只要登录，上面这些写接口全部放行。

## 已定下来的行为

1. 勾选粒度是场景。知行录拆成 TED、运动、书/电影三个勾，三者互相独立。零钱罐子与它们并列，共七个场景。
2. 未勾选是「能看不能改」。入口和页面都留着，前期要把功能放出来让人感知到。输入、保存、添加、删除、会改数据或调用模型的按钮禁用，并标「当前仅可查看」。写接口同时拒绝，不能只藏按钮。
3. 周期长度不进这份配置。双周、季度的长度继续写在现有周期/阶段表里，以后用 `user_id` 区分各人的数据即可。
4. 全局默认写在配置文件的环境变量里，不进数据库，也没有人在页面上改它。
5. 每个登录用户在弹窗里只改自己的勾选。没存过的人用环境变量里的默认。不设管理员账号，也不做「谁可以改全局」的资格。

顶部「莱特纳盒子学习法」链到 `codingwithalice.top:4001`，不在这七个场景里。

## 配置存什么

场景名单写在代码里：key、显示名、对应页面、对应写接口。新增场景改代码。

默认值必须来自配置，代码里不设「没写或解析失败就七个全开」。本地读环境变量，线上读配置文件 `config.env`，两边都会写上 `CAPABILITY_DEFAULT`。例如：

```bash
CAPABILITY_DEFAULT=daily,week,month,ted,sport,media,piggy
```

这份默认不是给日常勾选用的。要改它，改本地环境变量或线上配置文件后重新加载。

每个人真正勾过的结果进数据库。表里只有用户行，没有 `scope`，也不再为全局插一行：

`capability_config`

| 列 | 含义 |
| --- | --- |
| `user_id` | 哪个用户 |
| `enabled_json` | 该用户勾中的 key 数组，例如 `["daily","week","piggy"]` |
| `updated_at` | 什么时候保存的 |

这里用 key，不用数字 id 映射表。场景名单在代码里：页面、写接口、弹窗文案都靠 `daily` 这种字符串对上。再造一张 `id → key` 的表，代码和数据库就有两份名单，加一个场景要改代码还要插一行 id，两边可能对不齐。

数据量小不是原因。一份勾选只是「这个用户开了哪些 key」，读的时候整份拿出来用，不需要按场景 id 去关联查询。

生效规则只有一条，第一期和第二期用同一套代码：

1. 当前用户在 `capability_config` 里有行，用这行的 `enabled_json`。
2. 没有行，用环境变量 `CAPABILITY_DEFAULT`。

个人行一旦存在，就盖过环境变量，不用改环境变量，也不用把默认「降级」。还没保存过的人继续走默认。用户第一次在弹窗里保存，才插入自己的行。

不用 localStorage。换浏览器会丢，也挡不住直接调接口。

## 谁能改

弹窗只写当前登录用户自己的行：`user_id` 来自这次请求解析出的用户，不能在请求体里指定别人。

没有管理员。全局默认不在页面上改，改配置文件即可。现有的主账号继续只用于旁观者查看数据，场景开关的代码里不比较是不是主账号。

旁观者没有自己的 `user_id`，不显示弹窗，也不能保存。他们的查看仍走现在的旁观者规则。

## 七个场景和写接口

| key | 弹窗里的名字 | 未勾选时拒绝的写操作 |
| --- | --- | --- |
| `daily` | 晨昏日志 | `/api/daily`、`/api/daily/issue`、`/api/routine`、`/api/ai/parse-time`、`/api/ai/parse-issue` |
| `week` | 双周扫描 | `/api/week`、`/api/serial`、`/api/week/period` |
| `month` | 季度沙盘 | `/api/month` 及其 detail / synthesize / merge-structured |
| `ted` | TED | `/api/ted`、`/api/ted/record` |
| `sport` | 运动 | `/api/sport`、`/api/running-plans` |
| `media` | 书 / 电影 | `/api/books` 及上传 |
| `piggy` | 零钱罐子 | `/api/piggy-bank` 及其子路径、罐子图片上传 |

GET 不看这份勾选。查看沿用现在的数据隔离：登录看自己的，旁观者看主账号的。

周期起止、阶段覆盖哪些周期，仍走现有周期表和阶段表，不出现在这张勾选里。

## 弹窗

放在顶栏，现有「已登录 / 登录」旁边，入口文案用「场景」。登录用户都能打开，看到七个勾选。打开时如果自己还没有行，勾选状态先按环境变量的默认显示；一点保存就写入自己的 `user_id`。保存后当前页的可编辑状态更新。

未勾选的场景仍然可以点进去看。首页入口、页内切换日期或周期、已有内容的展示都保持可点。禁掉的是改数据的操作：输入、保存、添加、删除，以及会写入或调用模型的按钮，并标明当前仅可查看。

## 请求怎么被拦住

旁观者规则不动：没登录，非 GET 仍是 401；AI 接口旁观者连 GET 也不放。

已登录的写请求再加一层：

1. 用路径归到上面的某个 key。归不到的写接口保持现状。
2. 按生效规则算出 `enabled`。key 在里面，放行。
3. 不在，返回 403，文案与页面一致：「该场景当前仅可查看」。

配置接口：

- `GET /api/capabilities`：返回当前用户生效的 `enabled`，以及这份结果来自自己的行还是环境变量默认。某个 key 不在 `enabled` 里时，该场景仍可进入查看；页面只禁用这一场景里改数据的操作，不禁用进入和浏览。
- `PUT /api/capabilities`：只写入当前登录用户自己的行。

前端判断按 key 来：日报看 `daily`，知行录按当前页签看 `ted` / `sport` / `media`，零钱罐子看 `piggy`。名单只维护在注册表里。
